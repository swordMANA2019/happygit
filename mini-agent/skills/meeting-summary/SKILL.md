# 会议纪要

## 流程

1. **读完整份记录再写**。记录很长时（几千行、多个文件），先 `update_plan`，用 `delegate` 把记录按时间段/文件拆给子 Agent，
   每个子任务要求返回固定结构：`议题 / 关键发言要点（谁说了什么）/ 决定 / 待办 / 分歧`，你再合并。
   用 `save_notes` 记下与会人、会议目的、已确认的决定，防止后面被压缩丢掉。
2. **只写记录里有的信息**。没有明确说出的负责人/截止日期，写"未指定"，不要猜；听不清/有歧义的地方标注"（待确认）"。
3. **输出结构**（Markdown，保存为 `meeting-summary.md`，除非用户指定了别的位置/格式）：

```
# <会议主题>（<日期>）
参会人：…
## 一句话结论
## 决策
- …（谁决定的 / 依据）
## 待办事项
| 事项 | 负责人 | 截止时间 | 备注 |
## 讨论要点（按议题）
## 未决问题 / 需要跟进
```

4. **自检**：对照原文核对——每条决策和待办都能在记录里找到出处；人名、数字、日期逐项核对；没有遗漏被多次提到的议题。
5. 最后向用户汇报：文件位置、你标注了"待确认"的地方、以及你做的任何假设。

## 注意

- 保留原话中的关键数字、专有名词，不要意译。
- 涉及敏感内容（薪酬、人事）按用户要求处理，不要擅自外发。
